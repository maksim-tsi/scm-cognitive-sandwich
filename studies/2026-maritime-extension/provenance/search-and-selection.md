# Existing-source search and publication decisions — 1 November 2026

The search is bounded to existing local source/code refs and retained accepted-run
artifacts. It does not authorize model calls, remote machines, new cases or new
model answers. Source repositories remain unchanged.

## Search requirements

1. Search tracked manifests/contracts and original source before writing adapters.
2. Locate exact code by source path, commit and recorded hash; reuse verbatim
   implementations or inspection excerpts. Do not regenerate scientific logic.
3. Consult the accepted scientific namespace only for stored inputs, checkpoints,
   terminal records and output artifacts. Never read credential/configuration files.
4. Bind any recovered response to an original artifact hash. Distinguish raw
   serialized text, parsed JSON and controller projections; never fill missing text.
5. Require a matching predispatch input binding before calling an input set the
   executed scientific cohort. A plausible reconstruction is insufficient.
6. Search later development refs separately. Do not infer scientific results from
   qualification/smoke outcomes, and do not combine their denominators.
7. Export only source-qualified scientific material; scan paths, endpoints,
   identifiers and credential patterns, not merely file extensions.

## Export decisions

| Material | Decision and basis |
| --- | --- |
| Initial/repair templates | Export verbatim. The same files/builders survive unchanged from launch. Their earlier directory name does not change the executed direct-provider profile. |
| Prompt/schema/DES projection/identity functions | Verbatim inspection excerpts. No live launcher or provider construction is imported. |
| Phase-A input file | Export existing 180 design units for 60 incidents and three generation indices, with declared hashes. This is not the certified executed 60-unit scientific population. |
| Saved DES allocations | Export all 35 retained projections, not a hand-picked success subset. |
| Canonical parsed responses | Recover 27 distinct JSON objects by reversing only the documented DES metadata projection; verify every canonical hash against original terminal records. |
| Original serialized responses/full rendered requests | Not recovered from the searched accepted-run checkpoint/output files. Do not infer whitespace, API envelopes or omitted failures. |
| Later forwarder records | Bounded status/count extracts, source hashes and purpose-qualified index; no deployment details or trace identifiers. |
| Complete launchers, raw logs, private paper/reviews, infrastructure/configuration | Exclude: not required for retained-summary reproduction and create unnecessary exposure/coupling. |

## Material limitations

The saved DES projection adds generation_id and replaces condition. For zero-repair
reuse, the original condition was llm_only. Removing/restoring only those fields
recovers original canonical artifact hashes for all 35 projections (27 distinct
responses). These are recoverable parsed records, not original wire text. They
are success-conditioned retained material; they cannot represent all 344 operations
or characterize failed-output frequencies. Original terminal rows remain the
statistical population.

The original Phase-A inputs and identity mapper match their launch versions.
A local investigation of the identity-mapped candidate did not reconcile the
recorded scientific unit_set_sha256
`4d94fc7ff51bb6d0aff338a77d36a4958dd00e74ab4c4c8ba10c327f1e7dd708`.
No reconstructed candidate is published as the executed population. Full input/
prompt/response end-to-end replication therefore remains unqualified. This does
not change the exact reproduction of retained terminal-record analysis.

No data are invented to close these gaps. Further recovery would require an
existing exact execution dump or a documented reconciliation of its frozen binding,
not another experiment or new scenario generation. IDWL preservation is accepted
as sufficient; this task does not require a paper-section or runtime adjudication.
