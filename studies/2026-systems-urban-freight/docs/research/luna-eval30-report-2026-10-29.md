# GPT-6 Luna: separate EVAL30 extension

**Collection:** 29 October 2026. One separately authorized GPT-6 Luna trajectory for each of the existing 30 frozen scenarios. This is a later extension of the original three-provider evaluation, not an originally randomized or preregistered fourth arm. All 30 trajectories reached a schema-valid `FINAL`; 48 Responses API request intents and 48 completed responses are in the durable journal. No request or trajectory was retried or replaced; no route was isolated and journal STOP remained null. No new enriched four-provider cohort was run.

## Serving profile and evidence

`gpt-6-luna` via Responses API, JSON-object output, `reasoning.effort=none`, temperature 0, `max_output_tokens=2048`, `store=false`, no provider-native tools or images. Each scenario starts with explicitly constructed public messages. All original assistant output items and phases are replayed in order within the same scenario; only the unique `final_answer` action is passed to the unchanged canonical validator and controller. `ASK_USER` and `CALL_TOOL` return the same scenario-controlled records and limits as the original arms. Commentary is not executed. The replay is provider-specific and can change model context relative to the other profiles; provider, profile and gate effects cannot be isolated by this comparison. The unchanged controller, solver, evaluator, I2/I3 and public prompts were used; original EVAL30 cases, reference outcomes, prior captures and scores remain byte-identical.

The preflight (`luna-eval30-preflight-2026-10-29.md`; original source artifact, not included here) verified actual development `CALL_TOOL → FINAL` and `ASK_USER → FINAL` trajectories, their exact replay and observations, and the original freeze manifest. It fixed the profile before scientific collection and distinguished case-level model-format errors from global technical stops. The prior failed smoke and development trajectories are separate from this arm.

For Luna the 16 correct outcomes are 13 correct feasible plans and 3 justified insufficient-evidence decisions; none of the four reference-infeasible cases received a correct infeasibility decision. I2 admitted 16 and I3 admitted the same 16; I3 did not increase the number of useful outcomes. These are single observed trajectories under the specified synthetic premises; they do not establish general model ranking, causality, real-world delivery benefit or architecture superiority. A deterministic baseline uses no model generation and is not a model treatment.

The 15 normalized cases yielded 12 correct outcomes; the 15 interpreted-message cases yielded 4. These strata contain different cases, so the observed difference is not a controlled causal effect of presentation. Luna issued six atomic questions and 13 tool calls across its 48 responses. All cases reached FINAL; 14 did not meet the full decision contract. Component diagnostics overlap and are conditional on a terminal proposal: six returned routes were infeasible on the reference instance; three cases cited nonliteral or unknown IDs; one showed an action-semantics error; one cited a temporal/superseded source; three had an unnecessary refusal under the frozen reference. EVAL29 was an unnecessary `INSUFFICIENT`, not an observed unit-conversion or clearance success. Zero flagged numeric-parameter errors in this diagnostic applies only to numeric terminal proposals with a reference oracle; it does not classify refusals as numerically correct. Per-case status, true-instance violations, source errors and gate decisions are in `evidence/luna-eval30/analysis.json` and `episodes.csv`.

No unsupported numeric proposal was admitted by either gate under the source-frozen diagnostic; no additional I3 rejection of a fully correct I2-admitted proposal occurred. I2/I3 compare the same original terminal proposal, and their hashes matched on every available terminal replay. This study does not prove that I3 is complete against unconsulted or superseded sources, or that it prevented actual harm.

The returned model identity was consistently `gpt-6-luna`; an alias is not proof of immutable weights.

## Offline reproduction

Extract the capture archive into a fresh local directory, verify every file against `evidence/luna-eval30/manifest.json`, then run `python -m tools.openai_extension.prepare_analysis <extracted-directory> <new-adapter-directory>` and `python -m tools.openai_extension.analyze_scientific --input <new-adapter-directory> --output <new-analysis-directory>` with `PYTHONPATH=.:implementation/padua_evidence_v1`. These steps execute no model inference. Journal-only counts can be independently reproduced with `python -m tools.openai_extension.analyze_journal <extracted-directory> <new-output.json>`. Paths must be fresh to avoid overwriting retained evidence. The analyzer reports unknown usage separately; all 48 calls in this arm reported usage.
