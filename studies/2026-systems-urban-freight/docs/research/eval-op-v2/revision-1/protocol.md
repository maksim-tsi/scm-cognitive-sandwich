# EVAL-OP-V2-R1: candidate controlled context ablation

**Status: candidate for substantive researcher review; not approved, frozen, or authorized for inference.** The 16-case predecessor at `research/eval-op-v2/scenarios.json` and its references are preserved. ## Construct and comparison

The implemented contract tests evidence handling and computational decisions inside a synthetic operational world. It does not directly authenticate business identity, receiver permission, actual site entrance or road access. The preferred question is whether supplying dated, visually derived, non-authoritative text changes full-contract decision correctness, unsupported commitments or appropriate abstention under identical case inputs. Secondary research questions concern source handling, physical feasibility under the declared numeric world, action semantics and I2/I3 admission for the *same original proposal*. For this design, any effect includes added words, length, placement and qualification, not only the semantic information in the observation.

There are 16 enriched cases as the standalone candidate and 6 control variants paired with six of them. Each enriched trajectory is run once and reused in both standalone and paired analyses. Thus there are 22 distinct assignments per provider (not 28), 88 model trajectories in total plus 22 D-INT trajectories. The pair, not a variant, is the comparative unit. Conditions have separate conversations and exact identical IDs for the world, POI, sources and commitments, with an external assignment name for distinct journals. The machine-verifiable *only* within-pair difference is presence versus absence of `public.site_evidence`; complete world, routing, records, source availability, limits, reference, SYSTEM, evaluator, providers and model-visible IDs otherwise match. `pairs.json` records allowed differences and source evidence; `schedule.json` fixes assignment order.

The six pairs are OPV2-01 (ALDI, feasible), 02 (Lidl and user source, feasible), 03 (Komok unresolved, insufficient), 04 (Alimentari and tool source, feasible), 08 (competing active synthetic sources, insufficient), and 13 (indivisible-load infeasibility). The 16 enriched cases retain reference distribution 9 feasible / 3 infeasible / 4 insufficient; the six pairs are 3 / 1 / 2. For Lidl, the enriched record uses the April 2023 image showing a possible side opening, with its unknown function in a separate qualification field. All original UUIDs and image hashes/dates remain traceable. Control does not contain image-derived observation, while both versions expose the same historical POI registry labels with current identity unverified. These labels are not blinded and may themselves convey information.

R1 changes the precursor equally in both conditions: it removes `site_evidence_note`, which improperly disclosed conclusions, adds register labels, softens the claim about customer and freight entrances, and states an explicitly hypothetical modeled access premise. This premise does not locate a real service entry and the solver does not model vehicle height, road clearance or actual legal access. Both variants receive a common instruction that customer access alone does not establish freight access and that a curb alone does not establish permission. This primes the desired evidence boundary and can create a ceiling effect; the study asks about robustness under explicit rules, not unaided recognition. Some modeled permissions and service assumptions are unbound synthetic inputs; a missing numeric service source is only a proxy for missing evidence, not a direct identity/authorization validator.

## Prospective estimands and accounting

For each of the four providers separately, primary finite-cohort contrast is Δ = (1/6) Σᵢ (Yᵢ,E − Yᵢ,C), where Y is the existing source-first evaluator's full-contract correctness, including justified insufficiency. An observed invalid model response is Y=0. Do not substitute zero for unattempted, transport-uncertain, integrity-failed or otherwise technically missing assignments. Report all six paired values and +/-/0 directions. When any side is missing, report observed complete-pair mean as conditional and binary-outcome lower/upper bounds for the six-pair target; do not assume missingness is random, especially after global STOP. A terminal CLARIFY is a process outcome, not a completed supported decision; retain the inherited evaluator semantics.

Standalone results use all 16 enriched cases with separate observed, missing and assigned denominators. The pair-specific component analysis uses only six cases per condition; never compare the 16 enriched component counts to six controls as though paired. Report justified insufficiency, unnecessary refusal under both complete feasible and complete infeasible references, deferred clarification, numeric commitments without valid source grounding, unknown grounding, reference-world physical-plan errors when a full reference instance exists, submitted-parameter feasibility errors, action-transition errors, and source/provenance errors. Component denominators and missingness are explicit; categories overlap. The inherited evaluator only calls refusals unnecessary for feasible references, so report it separately from the predeclared broader refusal count over both complete reference outcomes. Its grounding=false flag combines parameter, acquired-source and citation mismatch; it does not by itself distinguish the source of the failure or identify cause. Cases with unresolved reference inputs are not assigned a fabricated true-world physical feasibility result. For every completed terminal proposal verify its hash equals both gate proposal hashes and report paired I2/I3 admissions, useful outcomes, unsupported admissions, additional rejections and correct proposals rejected. D-INT is reported separately as a deterministic comparator and is not averaged into the model estimate.

A canonical FINAL contains no required free-text rationale. Thus a wrong answer or unsupported numeric commitment does not establish that the model interpreted a particular sign, thought a side door was receiving, or mistook Vaillant for Komok. These are plausible mechanisms or individually adjudicated hypotheses, not automatically identified causal reasons. No image bytes are sent to any model. Source records and exact task-relevant text are identical across providers within a condition, subject to documented serving-profile differences.

Order is fixed before collection: three control-first and three enriched-first for each provider; for each pair, two providers see each ordering. The schedule rotates provider order and runs paired variants in independent, empty scenario-local histories. Any time, alias, rate, caching or server drift, and the absence of repeated draws at temperature zero, remain possible confounders. This is a descriptive within-case finite-cohort contrast, not a population-level causal claim, model ranking or proof of operational reliability. Cases share sites and mechanisms; OPV2-13 resembles EVAL30's indivisible-load mechanism. No model-specific tuning, case replacement or repeated enriched trajectory is allowed.
